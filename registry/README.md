# Agent registry summary

43 rows in `registry/agents/`, 46 files in `registry/evidence/` (one per row, plus `hosts`, `hosts-2`, `prior-art`). Date of research: 2026-09-29.

Citation style: a backticked id such as `codex` is the row `registry/agents/codex.json` and its evidence file `registry/evidence/codex.md`. `hosts` and `hosts-2` are `registry/evidence/hosts.md` and `hosts-2.md` (terminal hosts: cmux, tmux, iTerm2, kitty, Herdr, Zellij, Terminal.app and others). `prior-art` is `registry/evidence/prior-art.md`. `probe` is `tools/agents_probe.py`.

Read this first:

- Only `claude-code` was checked against a running instance. 39 rows are `documented`: read from vendor docs, public source or a downloaded binary, with no live turn seen. 3 rows are `inferred` (`conductor`, `pi`, `xcode-agents`). 42 of 43 rows have never been seen working on this Mac.
- Every CPU floor and hold window is a guess except the `claude-code` CPU numbers, the `codex` rollout gaps, and two idle Electron readings (`cursor`, `vscode-agents`). Where a number below is a guess, it says so.
- `herdr` is in this set (row and evidence, read at v0.9.1 and v0.9.2). It is a host, not an agent: it has no turn of its own.
- 21 rows are new since the 22-row version of this file: `auggie`, `claude-squad`, `cline`, `codebuddy`, `codebuff`, `conductor`, `continue`, `emdash`, `every-code`, `grok-build`, `herdr`, `jules`, `junie`, `kilo`, `kimi`, `kiro`, `mistral-vibe`, `openhands`, `qoder`, `trae`, `xcode-agents`.
- `probe` changed since the earlier version: it now evaluates `power_assertion` (name match, from `pmset -g assertions`), and `tool_children` counts direct children whose name is a shell. It still cannot evaluate `socket_activity`, SQLite reads, JSON fields, log lines or an open-turn record (`probe`).

Notes on rows people ask about:

- `herdr`: one binary, a client TUI plus a background `herdr server`. The server's direct children are pane shells and the agents are grandchildren, so the hosted agents match their own rows (`claude-code`, `codex`, ...) and Herdr must be treated as a container (`herdr`, `hosts-2`). Its per-pane state comes from screen manifests (title, OSC 9;4 progress, bottom of the screen), not from hooks, except for Pi, OMP, OpenCode, Kilo, Kimi and MastraCode (`herdr`, `hosts-2`). The socket is same-user, mode 0600, so no consent is needed (`hosts-2`). Herdr holds no sleep assertion and has no OpenTelemetry (`herdr`). The probe hides the server while its spawning client is alive, because it keeps the outermost match (`herdr`).
- `windsurf` is now Devin Desktop; the agent is Devin Local, the Devin CLI harness (`windsurf`).
- `codebuff` covers Codebuff, Freebuff and Freebuff Desktop; `vscode-agents` covers Cline, Roo Code (sunset), Kilo Code and Copilot in VS Code; `xcode-agents` covers the agents Xcode downloads (`codebuff`, `vscode-agents`, `xcode-agents`).

## 3. What needs specialisation

The generic detector is: match a process, then say "working" if it has a `caffeinate` child, a direct shell child, a transcript written in the last 30 s, or tree CPU over the floor (`probe`, `claude-code`). Where it goes wrong, with the smallest rule that fixes each:

| # | Case | Rows | What the generic detector does wrong | Smallest fix |
|---|---|---|---|---|
| 1 | Sleep inhibitor is an in-process assertion, not a `caffeinate` child | default on: `cursor`, `warp`, `zed`, `grok-build`, `junie`; opt-in or partial: `codex`, `copilot-cli` (GUI), `conductor`, `droid`, `vscode-agents` | `ps` shows nothing, so the session reads idle. | Use the `power_assertion` signal, which `probe` now reads from `pmset -g assertions`, and match on owner pid and assertion name from the row: `Codex is running an active turn`, `grok: agent turn in progress`, `Junie is working`, `Agent Mode request in-progress`, `Agent thread in progress`. Match the name as well as the pid: the `antigravity` IDE holds `NoIdleSleepAssertion` for its whole life. Copilot Local in VS Code keeps its blocker 2 minutes after a request ends (`vscode-agents`). `zed`: the pmset type label is unconfirmed, so key on pid and name. |
| 2 | `caffeinate` present while idle, or not a direct child | held while idle: `codebuddy` (the `--serve` daemon holds `caffeinate -i -w <pid>` for its whole life), `copilot-cli` (`keepAlive=on`); only valid in one shape: `kilo` (`-i -w <its own pid>`), `vscode-agents` (Kilo: only a direct child of the extension host with `-w` equal to its pid; other `caffeinate` in the VS Code tree belongs to terminals) | An idle daemon reads working forever, and an unrelated `caffeinate` in an IDE tree reads as an agent. | Count `caffeinate` only as a direct child, only in rows that list it, and where the row says so require `-w <that pid>`. ## 4. Recommended defaults for the generic detector

Evaluate in this order. Any one true means working. Idle means every signal absent for the hold window. Report two states, working and idle, plus `unknown` for a host with no per-thread signal (case 5).

```
 1  exact turn state      row-specific: open-turn record + live pid, status row, lease, HTTP or socket state   [where the row has one]
 2  sleep inhibitor       direct-child caffeinate (rows that list it)  OR  IOKit assertion (pid + name from the row)
 3  direct tool child     shell child, or a new non-ignored child (rules below)
 4  transcript write      within 30 s   (raises working, never lowers it)
 5  tree CPU              >= floor      (fallback)
                          |
       all absent for the hold window (30 s)  ->  idle
```

**CPU floor: 3% of the process tree for a CLI or TUI; 10% for Electron IDEs, desktop hosts and terminal hosts.**
- 3% sits between the only measurement (`claude-code`: 9 to 11% working, under 1% idle) and the 27 rows that already use 3 (`aider`, `antigravity`, `auggie`, `claude-code`, `cline`, `codebuddy`, `codebuff`, `codex`, `copilot-cli`, `crush`, `every-code`, `gemini-cli`, `goose`, `grok-build`, `herdr`, `jules`, `junie`, `kimi`, `kiro`, `mistral-vibe`, `openclaw`, `openhands`, `qoder`, `qwen-code`, `trae`, `windsurf`, `xcode-agents`).
- 10% follows `cursor`, `vscode-agents`, `warp`, `emdash` and `continue`. The first four hold editors, shells and language servers (idle Cursor tree 0.5 to 1.0%, idle Electron tree 0.0%; `cursor`, `vscode-agents`). `continue` uses 10 because an idle TUI spawns an `osascript` child every 2 s and `ps` reports a short-lived child's CPU as a lifetime average, so a sample can spike (`continue`, inferred).
- The 5% rows (`amp`, `claude-squad`, `conductor`, `droid`, `hermes`, `kilo`, `opencode`, `pi`, `rovo-dev`, `t3-code`) are guesses. Start at 3% and raise per row after a live run.
- These are guesses in 42 of 43 rows. CPU never proves idle: network waits burn none (15 rows in section 2). A working `claude-code` session sat at 2.6% (`claude-code`).

**Hold window: 30 s.**
- The 30 s comes from the only measurement, `codex`: 20 s misses 7.3% of in-turn gaps, 30 s misses 4.2%. 21 rows use 30 s, 12 use 20 s, `crush` 15 s, `emdash` and `t3-code` 10 s; all unmeasured. `crush` can stay short because it writes every delta (`crush`).
- Keep an open-turn record working past 30 s while its pid is alive, because tool calls run up to 528 s (`codex`) and a Claude Code session showed 8 minutes with no feed event during one tool call while `caffeinate` stayed on (`hosts`).
- Add a 5 s debounce on level signals (`caffeinate`, assertion, tool child). `qwen-code` says its `caffeinate` drops for an instant between stream end and tool start; `warp` says its assertion is per request and can drop between two requests. The 5 s is my choice, not measured.

**Child processes that count as tools:**
- Count a direct child of the matched process whose name is a shell: `bash`, `zsh`, `sh`, `dash`, `fish` and the login forms `-bash`, `-zsh`, `-sh` (the `probe` set, which is also what the schema says `tool_children` counts). Shell tool calls are direct children in `amp` (`bash -c`), `goose` (`$SHELL -c`), `kilo` and `opencode` (detached shell), `pi`, `kimi` (`/bin/bash -c`), `qoder`, `continue` (`$SHELL -l -c`), `mistral-vibe` (`$SHELL`), `junie` (`bash -lc`), `grok-build` (login shell per call), `auggie`, `cline`, `every-code`, `trae` (trae-agent). `aider` spawns children for `git`, `/run` and test or lint commands.
- Optional, proposal: also count a direct child that was absent at the last idle sample and is not ignored (case 9). This covers `zsh -c` exec-in-place. It needs the detector to keep one sample of state.
- Turn `tool_children` off for the rows in case 8, where a permanent child or a host with pane shells would mark an idle session working forever. The same holds for surfaces whose tools sit two levels down (`kiro`; `mistral-vibe` Rust TUI, whose tool shells are grandchildren under `vibe-app-server`).
- Never count: `caffeinate` (it is signal 2); notification helpers (`afplay` for `amp`, `terminal-notifier` or `osascript` for `herdr`, `osascript` for `auggie`; these mean "waiting" or "done", not a tool); a child with the same executable as its parent (`gemini-cli`, `qwen-code` relaunch; `droid exec`; `amp` plugin runtime run with `BUN_BE_BUN=1`; a `kimi` auto-update respawn); package launchers (`npx`, `uvx`); MCP servers; and `language_server_macos_arm` (`antigravity`, `windsurf`). One exception to the same-executable rule: `codebuff` lists its own `--terminal-command-broker` child by name because that child is the tool signal.
- Do not count descendants, only direct children (schema and `probe`). Where the process a user sees is not the process that works (case 11), read the daemon instead.
