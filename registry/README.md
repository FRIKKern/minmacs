# Agent registry summary

63 rows in `registry/agents/`, 66 files in `registry/evidence/` (one per row, plus `hosts`, `hosts-2`, `prior-art`). Date of research: 2026-09-30. It replaces the 43-row draft of 2026-09-29.

Citation style: a backticked id such as `codex` is the row `registry/agents/codex.json` and its evidence file `registry/evidence/codex.md`. `hosts` and `hosts-2` are `registry/evidence/hosts.md` and `hosts-2.md` (terminal hosts: cmux, tmux, iTerm2, kitty, Herdr, Zellij, Terminal.app and others). `prior-art` is `registry/evidence/prior-art.md`. `probe` is `tools/agents_probe.py`.

Read this first:

- Only `claude-code` was checked against a running instance (1 row `verified-locally`). 59 rows are `documented`: read from vendor docs, public source or a downloaded binary, with no live turn seen. 3 rows are `inferred` (`conductor`, `pi`, `xcode-agents`). 62 of 63 rows have never been seen working on this Mac.
- Every CPU floor and hold window is a guess except the `claude-code` CPU numbers, the `codex` rollout gaps, and two idle Electron readings (`cursor`, `vscode-agents`). Where a number below is a guess, it says so.
- 20 rows are new since the 43-row draft: `agent-deck`, `autohand`, `claw-code`, `codewhale`, `command-code`, `deepagents`, `deepseek-harness`, `devin`, `freebuff`, `fx`, `grok-bot`, `letta`, `mastracode`, `mimocode`, `muse`, `omp`, `orca`, `prime-agent`, `superset`, `vibe-kanban`.
- `grok-bot` (Grok Bot, the xAI and Cursor desktop app) is in, as its own row. It is a client of Bots that run on a Cursor-hosted cloud computer, so a Mac can see the app and nothing about a turn (`grok-bot`). It is not Grok Build: that is the `grok` CLI, a different product with its own store under `~/.grok` (`grok-build`). `agent-deck` cannot host it, because it never appears in a tmux pane (`agent-deck`).
- Some rows are hosts or managers with no turn of their own: `herdr`, `agent-deck`, `claude-squad`, and the orchestrators `orca`, `superset`, `vibe-kanban`, `emdash`, `conductor`, `t3-code`. Their table entry is the host's own state. The agents inside them match their own rows.
- `probe` changed since the 43-row draft. It now reads the true argument vector from the kernel (`KERN_PROCARGS2`), so a path with spaces matches and `--flag=value` is parsed (`probe`, checked on a synthetic argv: `--session-id=abc` gave `abc`). It still keeps only the outermost match, and only when the parent matches a surface of the same row. It evaluates `child_process`, `tool_children` (direct children whose name is a shell) and `power_assertion` (substring of the `named:` string from `pmset -g assertions`). It still cannot evaluate `socket_activity`, SQLite reads, JSON fields, log lines or an open-turn record, and it reads neither `host` nor `oneshot` (`probe`). `transcript_write` fires only when a row has `per_session` and the process carries a session id.
- Local checks made for this file, read-only, 2026-09-30: `ps -axo pid=,ppid=,pcpu=,tty=,args=` (section 2, rows 1 and 2); `ps -axo pid=,pcpu=,etime=,time=,comm=` (section 4); and `probe.matches()` run on synthetic command lines against every row (section 3, cases 12, 15, 16, 23).

## 4. Recommended defaults for the generic detector

Evaluate in this order. Any one true means working. Idle means every signal absent for the hold window. Report two states, working and idle, plus `unknown` for a host or client with no per-thread signal (case 5) and `client only` for cloud work (case 19).

```
 1  exact turn state      row-specific: open-turn record + live pid, status row, lease, HTTP or socket state   [28 rows tagged R, plus S rows once set up]
 2  sleep inhibitor       direct-child caffeinate (rows that list it)  OR  IOKit assertion (owner pid + exact name from the row)
 3  direct tool child     shell child, or a new non-ignored child (rules below)
 4  transcript write      within 30 s   (raises working, never lowers it)
 5  tree CPU              >= floor      (fallback)
                          |
       all absent for the hold window (30 s)  ->  idle
```

**CPU floor: 3% of the process tree for a CLI or TUI; 10% for Electron IDEs, desktop hosts, terminal hosts and the two TUIs with known idle wakeups.**
- 3% sits between the `claude-code` measurements (9 to 11% working, under 1% idle; today 5.6 to 15.4% working, 0.0 to 0.1% idle) and the 40 rows that already use 3 (listed in section 2). One working session read 2.6%, so CPU alone misses some turns.
- 10% follows `continue`, `cursor`, `deepseek-harness`, `emdash`, `grok-bot`, `mimocode`, `orca`, `superset`, `vibe-kanban`, `vscode-agents`, `warp`. Most are editors, desktop hosts or hosts of shells and dev servers (idle Cursor tree 0.5 to 1.0%, idle Electron tree 0.0%; `cursor`, `vscode-agents`). `continue` uses 10 because an idle TUI spawns an `osascript` child every 2 s, and `mimocode` because its default `vivid` visuals animate an idle TUI (both inferred).
- The 5% rows (`agent-deck`, `amp`, `claude-squad`, `conductor`, `droid`, `hermes`, `kilo`, `opencode`, `pi`, `rovo-dev`, `t3-code`) are guesses. Start at 3% and raise per row after a live run.
- `ps` `%cpu` on macOS is a recent, decaying average, not a lifetime ratio: pid 8901 showed 58.2% with 100:10.96 of CPU time over 11:04:06 elapsed, a lifetime ratio of 15% (`ps -axo pid=,pcpu=,etime=,time=,comm=`, 2026-09-30). So a turn that has just ended can still read above the floor for a short time (my inference from the decay, not measured). Another reason CPU can raise but should not end a turn.
- CPU never proves idle: network waits burn none (19 rows in section 2). These floors are guesses in 62 of 63 rows. `zed` has no CPU signal.

**Hold window: 30 s.**
- The 30 s comes from the only measurement, `codex`: 20 s misses 7.3% of in-turn gaps, 30 s misses 4.2%, p99 is 56.8 s. 33 rows use 30 s (`auggie`, `claude-code`, `claw-code`, `cline`, `codebuddy`, `codebuff`, `codex`, `command-code`, `conductor`, `continue`, `copilot-cli`, `deepagents`, `deepseek-harness`, `droid`, `every-code`, `freebuff`, `fx`, `goose`, `grok-bot`, `grok-build`, `junie`, `kimi`, `kiro`, `letta`, `mistral-vibe`, `muse`, `omp`, `openhands`, `prime-agent`, `qoder`, `trae`, `vibe-kanban`, `xcode-agents`), 14 use 20 s (`aider`, `antigravity`, `cursor`, `devin`, `gemini-cli`, `hermes`, `openclaw`, `pi`, `qwen-code`, `rovo-dev`, `superset`, `vscode-agents`, `windsurf`, `zed`), 2 use 15 s (`autohand`, `crush`), 3 use 10 s (`emdash`, `orca`, `t3-code`), 11 have no transcript window (`agent-deck`, `amp`, `claude-squad`, `codewhale`, `herdr`, `jules`, `kilo`, `mastracode`, `mimocode`, `opencode`, `warp`). All unmeasured. `crush` can stay short because it writes every delta, but a long tool run still goes quiet.
- The window applies to raise-only signals: transcript write, shell child, CPU. A level signal (caffeinate, assertion) or an exact state is taken as it is, with no window.
- Keep an open-turn record working past 30 s while its pid is alive, because tool calls run up to 528 s (`codex`) and a Claude Code session showed 8 minutes with no feed event during one tool call while `caffeinate` stayed on (`hosts`).
- Add a 5 s debounce on level signals (`caffeinate`, assertion, tool child). `qwen-code` says its `caffeinate` drops for an instant between stream end and tool start; `warp` says its assertion is per request and can drop between two requests. The 5 s is my choice, not measured.

**Child processes that count as tools:**
- Count a direct child of the matched process whose name is a shell: `bash`, `zsh`, `sh`, `dash`, `fish`, with or without the login dash (the `probe` set, and what the schema says `tool_children` counts). Shell tool calls are direct children in `amp` (`bash -c`), `goose` (`$SHELL -c`), `kilo` and `opencode` (detached shell), `pi`, `kimi` (`/bin/bash -c`), `qoder`, `continue` (`$SHELL -l -c`), `mistral-vibe` (`$SHELL`), `junie` (`bash -lc`), `grok-build` (login shell per call), `auggie`, `cline`, `every-code`, `claw-code` (`sh -lc`), `autohand` and `command-code` (`sh -c`), `letta` (`/bin/zsh -c`), `muse`, `trae` (trae-agent). `aider` spawns children for `git`, `/run` and test or lint commands. Only the mistral-vibe exec-in-place and the command-code stand-in have been tried locally; every other shell-child shape comes from source or docs, and for `every-code`, `codewhale`, `muse` and `grok-build` a sandbox wrapper or an exec in place may change what the direct child is called.
- Count the one same-executable child that is a signal: `codebuff` and `freebuff` CLI, `<same path> --terminal-command-broker`, by name, while a shell tool call runs. A sponsored (ads) run uses a sandbox broker instead and is missed. `freebuff` Desktop reads a `bash` child of the bun process, with two known false positives (an open terminal panel when `SHELL=/bin/bash`; a startup script for up to 120 s).
- Optional, proposal: also count a direct child that was absent at the last idle sample and is not ignored (case 9). It needs the detector to keep one sample of state.
- Turn `tool_children` off, or do not list it, for the rows where a permanent child or a host would mark an idle session working forever: `codex`, `gemini-cli`, `qwen-code`, `droid`, `t3-code`, `codebuff` CLI, `openhands`, `herdr`, `crush`, `emdash`, `kiro`, `agent-deck`, `claude-squad`, `orca`, `superset`, `conductor`, `cursor`, `vscode-agents`, `antigravity`, `hermes`, `fx`, `devin`, `deepagents` TUI, `prime-agent`, `vibe-kanban`, and surfaces whose tools sit two levels down (`kiro`, `mistral-vibe` Rust TUI).
- Never count: `caffeinate` as a tool (it is signal 2, and only in the rows that list it); notification helpers (`afplay` in `amp` and `fx`, `terminal-notifier` or `osascript` in `herdr`, `auggie`, `continue` and `vibe-kanban`; they mean "waiting" or "done", not a tool); a child with the same executable as its parent, except the `codebuff` and `freebuff` broker (`gemini-cli` and `qwen-code` relaunch, `droid exec`, `amp` plugin runtime with `BUN_BE_BUN=1`, `fx` helpers, a `kimi` update respawn); package launchers (`npx`, `uvx`, `node` launchers); MCP servers; LSP (`language_server_macos_arm` in `antigravity` and `windsurf`); `tmux attach-session` (`agent-deck`, `claude-squad`); the `/bin/sh` watchdog in `codebuff` CLI; helper apps such as `Copilot Computer Use` (`copilot-cli`) and the Grok Bot helper processes (`grok-bot`).
- Do not count descendants, only direct children (schema and `probe`). Where the process a user sees is not the process that works (case 11), fold the chain instead of dropping it.
