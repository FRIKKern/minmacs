Citation style: a backticked id such as `codex` is the row `registry/agents/codex.json` and its evidence file `registry/evidence/codex.md`. `hosts` is `registry/evidence/hosts.md` (terminal hosts: cmux, tmux, iTerm2, kitty and others). `probe` is `tools/agents_probe.py`.

## 3. What needs specialisation

A generic detector is: match a process, then say "working" if it has a `caffeinate` child, a transcript written in the last 20 s, or tree CPU over 3%, with "tool children" meaning any non-caffeinate descendant. That is what `probe` does, and it also skips `power_assertion` and `socket_activity` entirely (`probe`; `cursor`, `warp`, `zed` say so). Where it goes wrong, with the smallest rule that fixes each:

| # | Case | Rows | What the generic detector does wrong | Smallest fix |
|---|---|---|---|---|
| 1 | Sleep inhibitor is not a `caffeinate` child | in-process assertion: `cursor`, `warp`, `zed`, `codex`, `vscode-agents`, `droid`, `copilot-cli` (GUI) | Reads these as idle: `ps` shows nothing. | Add a signal that reads IOKit assertions by owner pid and assertion name (`IOPMCopyAssertionsByProcess`). Match name as well as pid: `antigravity` IDE holds `NoIdleSleepAssertion` for its whole life. Copilot Local in VS Code holds its blocker 2 minutes after a request ends (`vscode-agents`). |
| 2 | `caffeinate` held while idle, or not a direct child | `copilot-cli` (`keepAlive=on` holds it for the session); `vscode-agents` (Kilo: only a direct child of the extension host with `-w` equal to its pid) | Marks an idle session working. | Count `caffeinate` only as a direct child of the matched process, and where the row says so require `-w <that pid>`. |
| 3 | Inhibitor drops while waiting | `cursor`, `zed`, `qwen-code` | Waiting on approval reads as idle. | Report only working or idle. Take "waiting" from a hook or host event, never from CPU or absence (`hosts`). |
| 4 | Status stays "working" while waiting | `hermes` (lease keeps refreshing), `opencode` (`busy` during a permission wait), `vscode-agents` (Cline `running` during approval) | Waiting reads as working. | Same as 3. Where a row has a wait signal, use it to override. |
| 5 | Host process holds many sessions | the 12 rows in section 2 | One row, one state, for all sessions; or the wrong session gets a transcript. | Mark such surfaces `host: true`. Report the host process only, and attach a state to a session only when the row has a per-thread signal (`codex` lock, `hermes` lease, `t3-code` status, Cline `sessions.db`). Never map a host pid to a transcript file. |
| 6 | Shared database, no per-session file | `crush`, `goose`, `hermes`, `opencode`, `t3-code`, `vscode-agents`, `warp`, `windsurf`, `zed` | `probe` has no `per_session` path, so `transcript_write` never fires. A fresh `-wal` mtime says only that some session wrote. | Use the mtime only as a raise-confidence signal for a project with one live process. For exact state, read the status row read-only (never the message columns). Needs a new signal kind; `hermes` proposes `sqlite_row`. |
| 7 | Quiet transcript during a live turn | the 10 rows in section 2 | A 20 s window calls a long model call or a long tool idle. `codex` data: 20 s misses 7.3% of gaps (127 of 1732), 30 s misses 4.2% (72 of 1732), max gap 528 s. | A transcript write may raise "working" but never lowers it. Prefer an open-turn record: `codex` (`task_started` without `task_complete`), `copilot-cli` and Copilot Local (`assistant.turn_start` without `turn_end`). Keep an open turn working only while its pid is alive: `codex` `inProgress` stays set forever after a crash. |
| 8 | Long-lived children | MCP, LSP or relaunch children: `antigravity`, `codex`, `crush`, `cursor`, `droid` (persistent `droid exec`), `gemini-cli` (relaunch), `qwen-code` (relaunch), `t3-code` (provider children), `warp` (`terminal-server`); listed with a warning: `aider`, `amp`, `goose`, `opencode`, `pi`, `rovo-dev`, `windsurf` | "Any non-caffeinate child" reads idle sessions as working forever. 16 rows are affected. | See section 4, tool children. |
| 9 | Name or path shared with another program | `amp` (text editor), `copilot-cli` (AWS Copilot), `crush` (not checked), `gemini-cli` (Gemini-protocol clients), `goose` (pressly migration tool), `hermes` (Pandora client `Hermes.app`), `opencode` (archived Go project, same `~/.opencode/bin`), `rovo-dev` (Acquia `acli`), `warp` (MinIO) | Reports an unrelated program as an idle agent. | A name match alone is not enough for these names. | 10 | Interpreter is the process | `aider` (python), `cursor` CLI (node), `gemini-cli`, `qwen-code`, `pi`, `openclaw`, `hermes` (python), `t3-code` (npx) | Name match finds nothing, or every node script. | Match on argv or script path. `openclaw` and `pi` retitle themselves, which replaces argv in `ps` on macOS (`openclaw`), so match the title too. |

| 15 | Electron IDE trees | `cursor`, `vscode-agents`, `warp`, `antigravity` IDE (a language server was reported at 400% with no agent) | Typing, a build in the integrated terminal, or a language server marks the app working. | CPU is a last resort here: floor 10%, never the only reason. |

## 4. Recommended defaults for the generic detector

Evaluate in this order. Any one true means working. Idle means every signal absent for the hold window.

```
 1  sleep inhibitor      direct-child caffeinate  OR  IOKit assertion (pid + name from the row)
 2  exact turn state     row-specific: open-turn record, status row, lease, wakelock   [where the row has one]
 3  new tool child       shell or non-baseline child (rules below)
 4  transcript write     within 30 s   (raises working, never lowers it)
 5  tree CPU             >= floor      (fallback)
                        |
      all absent for the hold window (30 s)  ->  idle
```

**CPU floor: 3% of the process tree for a CLI or TUI; 10% for Electron IDEs and terminal hosts.**
- 3% sits between the only measurement (`claude-code`: 9-11% working, under 1% idle) and 11 rows that already use 3 (`aider`, `antigravity`, `claude-code`, `codex`, `copilot-cli`, `crush`, `gemini-cli`, `goose`, `openclaw`, `qwen-code`, `windsurf`).
- 10% follows `cursor`, `vscode-agents` and `warp`, whose trees also hold editors, shells and language servers. An idle Cursor tree read 0.5-1.0% (`cursor`) and an idle Electron tree 0.0% (`vscode-agents`).
- The 5% rows (`amp`, `droid`, `hermes`, `opencode`, `pi`, `rovo-dev`, `t3-code`) are guesses. Start at 3% and raise per row after a live run.
- These are guesses in 20 of 21 rows. CPU never proves idle: network waits burn none.

**Hold window: 30 s.**
- The 30 s comes from the only measurement, `codex`: 20 s misses 7.3% of in-turn gaps, 30 s misses 4.2%. 13 rows use 20 s, 4 use 30 s (`codex`, `copilot-cli`, `droid`, `goose`), `crush` 15 s, `t3-code` 10 s; those are all unmeasured.
- Keep an open-turn record working past 30 s while its pid is alive, because tool calls run up to 528 s (`codex`) and a Claude Code session showed 8 minutes with no feed event during one tool call while `caffeinate` stayed on (`hosts`).
- Add a 5 s debounce on level signals (`caffeinate`, assertion, tool child). `qwen-code` says its `caffeinate` drops for an instant between stream end and tool start; `warp` says its assertion can drop between two requests. The 5 s is my choice, not measured.

**Child processes that count as tools:**
- Count a direct child of the matched process that is a shell (`bash`, `zsh`, `sh`) or that appeared after the process was last seen idle. Shell tool calls are direct children in `amp` (`bash -c`), `goose` (`$SHELL -c`), `opencode` and `pi` (detached shell per command). `crush` runs external commands as real children on macOS. `aider` spawns children for `git`, `/run` and test or lint commands.
- Take the baseline set of children when the process is first seen idle, and ignore those. That removes MCP servers, language servers and the persistent exec child in the 16 rows in case 8.
- Never count: `caffeinate` (it is signal 1), notification helpers (`afplay` for `amp`, `osascript` or `terminal-notifier` for `aider`; these mean "waiting" or "done", not a tool), a child with the same executable as its parent (`gemini-cli`, `qwen-code` relaunch; `droid exec`; `amp` plugin runtime run with `BUN_BE_BUN=1`), package launchers (`npx`, `uvx`), and `language_server_macos_arm` (`antigravity`, `windsurf`).
- Do not count descendants, only direct children. `probe` counts every descendant that is not `caffeinate`, which is why case 8 misfires.

## 5. Not verified

- 21 of 22 rows were never seen with a live turn. Every floor, window and process shape marked inferred in the rows should be checked on the first live run. `cursor` has real log lines of wakelock acquire and release from earlier turns, but no live assertion was watched.
- Signals the reference `probe` cannot evaluate today: `power_assertion`, `socket_activity`, log lines, and SQLite reads. A detector built from this file needs them added.
- `hosts` is measured on cmux 0.64.3 and tmux 3.6a only. iTerm2, Warp, WezTerm, kitty and standalone Ghostty are docs and source only.
